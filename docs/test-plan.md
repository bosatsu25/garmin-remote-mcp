### 4.1 チェックリストベーステスト：OWASP ASVS 5.0.0 V10

このサーバーの実体は OAuth の認可サーバー兼リソースサーバーなので、それを直接扱う V10 章を全件確認しました。要件の ID とレベルは、公式の 5.0.0 JSON リリースから生成しています。

| 分類 | 件数 | 内容 |
|---|---|---|
| テストで確認 | 17 | レベル1・2で、認可サーバーとリソースサーバーに当てはまる要件すべて |
| 該当なし | 13 | OAuth クライアント側の要件（クライアントは claude.ai）、OIDC の要件（ID トークンを扱わない）など。理由を1件ずつ記載 |
| 対象外 | 6 | レベル3（送信者制約付きトークン、PAR、公開鍵によるクライアント認証など）。このサーバーの目標はレベル2 |

[`tests/test_asvs_checklist.py`](../tests/test_asvs_checklist.py) が次を強制します。36件すべてが分類されていること、「確認済み」が指すテストが実在すること、レベル2以下の要件を「対象外」にできないこと。

V10.4.1 には1点だけ逸脱があります。要件は「文字列の完全一致」ですが、MCP SDK は正規化した URL 同士を比較します（`claude.ai:443` や `x/../auth_callback` は登録済み URI と同一扱い）。受理された場合でも、認可コードの送り先が登録済み URI そのものになることをテストで固定しています。

**V10 以外の章（V1〜V9、V11〜V17）は対応付けていません。** 関連する節（V3.4、V4.1、V6.2、V6.3、V7.4、V16.3）は目視で確認し、見つかった不足は7章に書いています。

### 4.2 探索的テストのセッション記録

- **チャーター**: 認証なしで届く範囲から、制限や検証をすり抜ける方法を探す。
- **対象**: 実際にビルドしたイメージを、読み取り専用ルート FS・全ケーパビリティ削除・非 root で起動したコンテナ。
- **試したこと**: 同時リクエスト、HTTP メソッドの差し替え、パスの変形（末尾スラッシュ、大文字、`//`、`;`、`%2f`）、Host ヘッダーの差し替え、巨大なヘッダーとパラメーター、フォーム項目の重複、Content-Type の取り違え、クライアント登録メタデータの悪用、未対応グラント種別。
- **結果**: 欠陥4件（6章の X1〜X4）。修正後に同じ手順を再実行し、解消を確認しました。
- **問題なしと確認したこと**: 未認証の `/mcp` はどのメソッドでも 401。`/docs` や `/openapi.json` などは存在しない。404 の本文に内部情報は出ない。70KB のヘッダーは 400。`client_uri` に `javascript:` を入れた登録は拒否される。

## 7. 残存リスク（テストでは消えないもの）

- **実際の Garmin API との結合は未検証です。** 偽 Garmin はシグネチャまでしか本物と一致させていません。デプロイ後、最初に `get_profile` と `create_workout` を1回ずつ手動で試してください。
- **プロンプトインジェクションは根本的には防げません。** Garmin のデータ（アクティビティ名など）に悪意ある指示が含まれる可能性はあります。サーバー側で保証できるのは、書き込み権限を許可していない接続では書き込みが**絶対に**通らないこと（R05）までです。書き込みを許可した接続では、クライアント側の確認（`destructiveHint`）に頼ることになります。
- **全体のロックアウトによる DoS**: 攻撃者は1時間に30回失敗するだけで、オーナーの新規接続を1時間止められます。既存のトークンは影響を受けません。パスワードの総当たりを防ぐことを優先し、この挙動は受け入れています。
- **Volume 上の Garmin トークンは平文 JSON（0600）です。** 暗号化しても、鍵は同じ環境の secret に置くしかなく、Volume を読める人は secret も読めます。そのため防御効果がほとんどないと判断し、実装していません。Fly の Volume 自体は保存時に暗号化されています。
- **オーナー認証は単一要素です（ASVS V6.3.3、レベル2を満たしません）。** パスフレーズが漏れると、第三者が接続を許可できます。対策を足すなら TOTP（認証アプリ）の追加が現実的です。
- **レート制限の状態はメモリ上にあります。** マシンが再起動すると数え直しになります。Fly の自動停止を挟めば、攻撃者は15分を待たずに次の5回を試せます。16文字以上のパスフレーズに対しては実用上の影響はありませんが、保証値としては「再起動ごとに5回」です。
- **ASVS は V10 章しか対応付けていません。**
- **実際の Docker イメージのビルドと起動は、この環境と CI の両方で確認済みです。** ただし Fly.io 上での動作（Volume のマウント、プロキシ経由のヘッダー）は未確認です。
